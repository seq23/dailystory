# Character System Migration Documentation

## Overview

This document outlines the comprehensive migration of the character consistency system from frontend to backend architecture, completed to eliminate dead code and improve system reliability.

## Migration Summary

### Before Migration
- **Frontend Character Logic**: 8 character methods in `SimpleImageService.ts`
- **Frontend Character Service**: `UnifiedCharacterConsistency.ts` with 500+ lines
- **Global Frontend Import**: Character service imported globally in `App.tsx`
- **Mixed Data Flow**: `totalPages` passed to backend for guest users
- **Frontend Monitoring**: Direct service imports in monitoring components

### After Migration
- **Backend Character Logic**: All character consistency moved to `supabase/functions/_shared/UnifiedCharacterConsistency.js`
- **No Frontend Character Service**: Deleted `src/services/UnifiedCharacterConsistency.ts`
- **Clean Frontend**: Removed global character import
- **Simplified Data Flow**: Pass `sessionId` and `isGuestUser` flag instead of `totalPages`
- **Backend Monitoring**: Centralized monitoring API at `get-monitoring-data`

## API Changes

### Frontend → Backend Data Structure
**Before:**
```typescript
{
  pageText: string,
  userInfo: UserInfo,
  storyId?: string,
  pageNumber?: number,
  totalPages?: number,
  difficultyLevel: DifficultyLevel
}
```

**After:**
```typescript
{
  pageText: string,
  userInfo: UserInfo,
  storyId?: string,
  sessionId?: string,
  pageNumber?: number,
  isGuestUser: boolean,
  difficultyLevel: DifficultyLevel
}
```

## Post-Migration Enhancement: Session-Seeded Hair Variety

### Date
**Implemented**: September 29, 2025

### Problem Identified
After backend migration, hair selection still had two issues:
1. `Math.random()` caused non-deterministic hair within same session
2. `userInfo.hair` override defeated backend consistency logic

### Solution Applied
**Session-Seeded Hair Selection**
- Added deterministic PRNG seeded by `sessionId`
- 73 hair variations mapped by skin tone
- Removed `userInfo.hair` override at generation time
- Result: Same character in same session = same hair

### Files Modified
- `src/services/SimpleImageService.ts` - Added seeded random functions (lines 876-947), removed hair override (lines 315, 685)
- `src/components/CleanStoryDisplay.tsx` - Pass sessionId consistently (line 2502)
- `src/types/api.ts` - Removed hairColor from avatar interface

### Architecture Impact
- **Before**: Random hair every generation (inconsistent)
- **After**: Session-determined hair (consistent + variety)
- **Backend**: Character consistency logic preserved
- **Frontend**: Session-aware hair selection complements backend logic

### Business Value
- ✅ Character consistency within sessions
- ✅ Natural variety between sessions  
- ✅ Cultural authenticity maintained (ethnicity overrides)
- ✅ No brown hair on light-skinned avatars (fixed poor mapping)
