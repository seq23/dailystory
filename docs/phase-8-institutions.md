# Institutions workspace — October 2026 Phase 8

This is the new institutions phase, independent of the older `PHASE_8_IMPLEMENTATION_STATUS.md`. The workspace is at `/schools`, linked from the adult sidebar. It supports school or district-operated groups through a school tenancy boundary. There is no institutional billing, pricing or sales material in this change.

## What works

Teachers create classes assigned to themselves, add child profiles, and record dated reading sessions and level/quiz observations. School administrators assign existing adult accounts as teachers, create classes for those teachers, filter across teachers/classes, and delete institutional children with their dependent records. Teachers cannot promote themselves, view another teacher's class, overwrite evidence, or claim another class's child by guessing its roster ID. School administrators have access only within their school.

Student and class reports show completed story sessions, recorded minutes, School grade, Reads at, and correct/total quiz counts for vocabulary, spelling, definitions, context and inference. Histories retain observation dates, recording timestamps, the recording adult and source. Records carry their source and are always labelled: **Teacher recorded** (entered in /schools) or **From the app** (see below). Household profiles on other accounts are never linked or ingested, and there is no student sign-in. A repeated completed reading session counts as another session, not a distinct book. The school workspace itself never calls story-generation, payment or email services.

CSV import previews up to 1000 rows and commits them atomically. Headers are `external_id,display_name,school_grade,reading_grade`; the two grade columns are optional. Use aliases and school-scoped roster IDs. Invalid grades, malformed quoting, unknown columns and duplicate IDs reject the file. UTF-8 BOM, CRLF, embedded commas/newlines and escaped quotes work. Reimport preserves existing profiles and grades, adding only missing enrollments. Importing does not create auth accounts. No source CSV is uploaded or stored.

The database RPC independently rejects duplicate/blank identifiers and nonminimal rows, including requests that bypass preview. Identifiers and names are trimmed before matching or insertion. Unsaved reading and assessment forms clear when switching classes or children, so a previous child's scores cannot carry into the next child's entry.

Both remote adapters implement the same `RosterAdapter` contract as CSV. An authenticated school-admin-only edge endpoint previews provider students, and the same transactional import RPC saves them into the selected class. Provider IDs are namespaced. Credentials are server-only, school-scoped, and never returned to the browser. Missing credentials show **Not connected**; configuration alone is labelled **Configured (not yet verified)**. Pagination is bounded; provider errors never substitute made-up students or blank existing records. No integration account was created and no live roster was fetched during development.

## App reading in the class view

Added 31 Oct 2026 by migration `20261031210000_institution_app_reading.sql` (additive). A teacher or school admin links a child profile **on their own account** (for example a classroom profile) to a roster child they can already see, under *Link an app profile to a roster child*. The RPC `institution_link_app_profile` requires both: profile ownership and class access. One profile per roster child. Unlinking (`institution_unlink_app_profile`, the profile owner or school admin) stops future copies and keeps recorded history.

While linked, triggers on the family tables copy, for every class the child is enrolled in, with source `app`, `recorded_by` empty and an `app_ref` naming the family row:

- each ended reading session (`reading_sessions`): story title when known, minutes the reading page was open (capped at 180), completed or not, words read, dated the day it ended;
- each in-app quiz with per-skill answers (`quiz_attempts.details.skillAnswers`): correct/total per class-view skill. The app's eight skills map to the five in one place, `institution_private.app_skill` (mirrored by `APP_SKILL_MAP` in `src/lib/institutions/report.ts`, and a guard keeps them equal): sight-words → vocabulary; phonics, spelling → spelling; word-meaning → definitions; what-happened, sentence-sense → context; between-the-lines, big-picture → inference. A quiz without per-skill answers is not assessed, never zero;
- each change of the profile's Reads at: one dated level observation.

Nothing read before the link is copied, so no baseline is invented. Rows are written only when the reading account owns the linked profile (a row naming someone else's profile is ignored). Browsers cannot write `source` or `app_ref`. A failure in the school copy is logged as a database warning and never loses the family's own record. Pages are not recorded by the app, so none are reported.

Reports keep the two sources apart and never add them together: class totals, quiz tables and growth are shown for teacher-recorded data, then separately *From the app*. App level growth compares the first and latest Reads-at settings the app recorded; it is a reading-difficulty setting, not an assessment, and the roster grade never stands in for it. The same observational rules apply: dated endpoints, two observations needed, question-weighted quiz totals, no causal or efficacy claim.

## School AI privacy lane

Any account that is an institution member or owns a linked profile, and any request naming a linked profile, is on the **school lane** (`public.institution_ai_lane`, service role only; `supabase/functions/_shared/privacyLane.ts`). The edge functions for story pages, quizzes, word definitions, translation and spelling resolve the lane from the verified account before calling the router; a signed-in account that cannot be confirmed is treated as school. In `storyTextProvider.ts` the school lane never tries the free OpenRouter models, and `assertSchoolSafeRequest()` checks every request before it is sent: Workers AI directly, OpenRouter only with `provider: { data_collection: "deny", zdr: true }` on a paid model, or OpenAI; names are masked on all three. If none answers, the caller's backup content is used. Pictures are off for school accounts (Runware keeps images 7 days without its enterprise Zero Data Retention, and its scene step uses the Lovable gateway). The reasons per provider are recorded in `config/product_inference.json` under `text_chain.school_lane`; the guard is `src/test/guards/school-privacy-lane.test.ts`. Family routing is unchanged. A teacher's own household profiles are also on the school lane, which is the stricter side.

## Connections and authority

`INSTITUTION_ROSTER_CONNECTIONS` is an edge-function secret containing a JSON object keyed by the internal school UUID. Each value can contain `clever: { token }` and `classlink: { token, applicationId }`. Populate this only in the authorized deployment environment; never put it in a `VITE_*` variable, source file, browser setting or GitHub issue. An absent school entry means disconnected. Tokens must be obtained by the owner through an existing authorized provider relationship; this workspace neither signs up for providers nor starts an OAuth consent flow.

Clever uses a district-app OAuth bearer with Secure Sync roster access: `GET https://api.clever.com/v3.0/sections/{id}/users?role=student`. Individual Clever SSO OAuth tokens do not provide section rostering. The [API overview](https://dev.clever.com/docs/api-overview) and [official schema](https://github.com/Clever/swagger-api/blob/master/v3.0.yml) describe this distinction. Next links must keep the same origin and class endpoint; redirects are refused.

ClassLink uses its Partner Portal OAuth2 Proxy bearer and application ID: `GET https://oneroster-proxy.apis.classlink.com/{appId}/ims/oneroster/v1p1/classes/{id}/students`. It follows limit/offset pagination and drops deleted users. This follows [ClassLink's connection guidance](https://help.classlink.com/articles/Knowledge/pp-access-rs-data) and the provider's [interactive API reference](https://oneroster-proxy.apis.classlink.com/docs/). This is not a generic OneRoster OAuth client-credentials implementation or LaunchPad SSO.

Before provisioning a real school, the owner must establish school authority, notices, consent basis and the applicable agreement. There is no self-service school/admin creation or automated school consent verification. An authorized operator creates `institution_schools` and a `school_admin` membership for an **existing** adult account; application clients cannot write either. The school admin can then assign teacher accounts in the UI. UUIDs, names and credentials of real institutions belong outside this public repository. Membership revocation and class reassignment currently require an authorized operator; teachers cannot do either.

## Growth methodology

Growth is observational, not proof of causation or a standardized assessment. Imported/current profile grades never manufacture a historical baseline. A student's first and last nonblank recorded reading-level assessments establish dated endpoints. Grade-step change uses the existing ordered grade list (PreK, K, 1–10); it is not a reading-age score. A single observation shows its date/level but no change. Blank later assessments do not erase earlier readings. Declines and explicit zero quiz scores remain visible.

Each skill compares its own first and latest recorded correct/total result and displays both dates. Change is in percentage points and needs two separate assessments. Class quiz percentages divide summed correct answers by summed question counts, not an average of percentages. Class mean level change includes only the same children with at least two recorded levels and displays paired/total coverage. Reports read every page of accessible rows rather than silently stopping at the Data API cap. No statistical significance, efficacy claim or invented test score is provided.

## Schema, validation and release

Migration `20261031050519_institutions.sql` creates eight new tables, an unexposed authorization-helper schema, RLS, indexes and narrowly authorized RPCs. It does not rewrite any family table, policy or existing row. Direct browser table grants are minimal. Privileged RPCs verify `auth.uid()` against stored membership, use a locked empty search path, and revoke anonymous/public execution. They do not trust user metadata. Composite foreign keys prevent cross-school enrollment and orphan reading/assessment writes.

`bash scripts/test-institutions-db.sh` uses a network-isolated disposable PostgreSQL 17 container pinned by image digest, installs this migration, and exercises real allow/deny queries, transaction rollback, reimport and cascading child deletion. Its bootstrap models Supabase's application roles and legacy permissive table grants; application assertions run after `SET ROLE authenticated`, without administrator or RLS-bypass privileges. It never reads production credentials. Regression tests also cover report math, CSV parsing, provider protocol/pagination, cross-school connection isolation and endpoint authorization. The CI fast gate runs these guards and the local database checks. See `docs/privacy/` for the data inventory, implementation-based legal readiness summary and NDPA exhibit worksheet.

Deployment is separate from code merge. **No production schema or database writes were performed for this change.** An authorized operator must apply the additive migration, provision an institution, configure any existing roster connections and deploy the edge function. The frontend requires Lovable Publish. The existing `.github/workflows/apply-migrations.yml` automatically applies new migrations on a merge to main. Consequently, `land`/merge must remain blocked under this job’s no-production-database-writes instruction; do not merge this PR as a way to bypass that restriction. Until those steps are verified, real-school acceptance and production rollout remain unproven. Local browser visual verification was unavailable in this session. The active Hallmark runner produced a source evidence pack outside the repo; it is evidence for review, not an external approval or a claim of complete production readiness.
